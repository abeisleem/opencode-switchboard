# T3 Code sidebar → terminal tab-panel research

Research date: 2026-10-26. Snapshot: `pingdotgg/t3code@1316d48b0c68151afd8b47eb0c11a114cf0b4daa`. Sources below were read over HTTP from pinned raw GitHub URLs. **Source** means wired behavior in this snapshot, not an independently tested release. **Beta** is explicitly labeled in docs; **Docs** denotes claims not traced through server automation. No existing research-note convention was found in dotfiles, so this uses the requested `.opencode/plans/` location. OpenCode API feasibility is outside this note.

## Inventory and semantics

| Area | Verified behavior |
| --- | --- |
| Organization — Source | One cross-environment list, scoped to **All projects** or a logical project. It is partitioned into pinned → active → Working → Snoozed → Settled, rather than nested project trees. Archived threads and subagent children are excluded. Project grouping can combine repository identities across environments, distinguish repository-relative project paths, or keep physical checkouts separate; overrides exist per physical project. Scope changes clear selection. [sidebar], [logic], [grouping] |
| Filtering/search — Source vs Docs | Inline sidebar search ranks **title, branch, PR** matches, then message-only results; it searches across its eligible shelves regardless of collapse state. Its scorer receives `threadSearchSubject(thread, null)`, so do not promise project-name matching there. **Docs:** the command palette additionally searches project names, uses recent/frequent opens and remembered query picks, and opens message matches at the matching message. Source deliberately disables pick-based reranking for the inline list and preserves message-result order as environments respond. No unread/status/provider filter was found in the current sidebar. [sidebar], [logic], [docs] |
| Pinned — Source + Docs | Persistent pin/order keys; pins precede active threads, including when working. Pin/unpin and reorder are capability-gated. **Docs:** pinning does not prevent automatic settlement; settling removes the pin. New pins receive a top-of-run key. Dragging across sections performs explicit state transitions. [sidebar], [logic], [actions], [docs] |
| Active — Source + Docs | With Working beta off, manual order is independent of streaming activity; new/unsettled keyless threads precede arranged threads. **Docs:** pin/snooze preserve active position; settle clears it. With beta on, active order instead follows return-to-user timestamps; manual active reorder is disabled without destroying the saved order. “Active section” is not synonymous with “selected/open thread” or “agent running.” [sort], [inbox], [docs] |
| Working — Beta, implemented | Default **on**, per-device setting. Working/resumable runtime states are folded below active; approval/input/subagent requests and actionable completed plans leave this category. Pinned threads remain pinned. Sort is latest user-authored send, with compatibility fallback. A two-second exit grace avoids flicker between continuations, bypassed for actionable results/errors or placement changes. **Docs:** includes awaited subagents, PR watches and background monitors, not an unattended dev server. [settings], [inbox], [docs] |
| Snoozed — Source + Docs | Explicit wake timestamp; sorted earliest wake first. Snoozing does not stop execution. Completion alone does **not** wake it. Fresh failures, pending approval/input/subagent/guest requests can wake early; an old failure predating snooze does not. Snooze is unavailable for pending requests or queued-start grace. Presets and custom date/time or duration are supported. **Docs:** a new user message also wakes it; snooze and auto-resume at usage reset are independent. [snooze], [docs] |
| Settled vs archive — Source + Docs | Settled is a recoverable shelf, not archive/delete; archive is a distinct single-thread menu action blocked while the provider is active. Settled is sorted by settlement time (with fallback timestamps), initially shows 10, then grows by 25, loading older pages. Working/Snoozed/Settled default collapsed, but retain the currently viewed row. **Docs:** server auto-settles after three inactive days or eligible PR closure/merge; running work and requests block it; manual un-settle suppresses auto-settlement until new activity. Idle terminals close with output retained; running commands remain. [sidebar], [sort], [menu], [docs] |

## Read/unread: important implementation details

- **Mark unread exists; a symmetric “Mark read” menu item does not** in either the current single or multi-select menu. It remains available on read-only connections. The hook sends a server `markUnread` command when visited tracking is supported; older servers use a local watermark. [menu], [sidebar], [actions]
- Sidebar unread is specifically **unseen completion**, not an unread-message count: valid `latestRun.completedAt > lastVisitedAt`. No completion, or no prior visit timestamp, produces no Done badge. “Done” appears only when higher-priority runtime/request/Woke status does not occupy the status slot. [logic], [row]
- The local fallback rewinds the visit watermark to **completion minus 1 ms**; without a valid completion it does nothing. Server-provided visit values take precedence over local values, including unread rewinds. The exact server rewind formula was not independently traced. [ui-state], [logic]
- Opening/viewing a thread mounts a visit tracker. It advances the watermark with shell updates, throttles streaming writes to 10 seconds, and dispatches completion/wake acknowledgement immediately. Deduplication against the last dispatched update keeps **Mark unread on the open thread sticky for that unchanged update**; a later update/remount may mark it read. This is mounted-view tracking, not proof that every message was read or the window was focused. [visits], [watermark]
- **Woke is separate from Done:** the row compares wake and visit timestamps and offers “Dismiss Woke notification,” acknowledging the wake without opening the conversation. [row], [actions]

## Row and action inventory

- **Card:** project/favicon, pin, title, unsent-draft marker, status or age, branch/worktree indicator, remote-machine/provider-history icons, running-terminal button, PR badge. Tooltip adds environment, model/provider, handoff history, branch-mismatch warning, running-process count and error/usage-limit information. Shelf rows are slim; the enabled redesign hides their PR badge. **Trap:** insertion/deletion rendering exists, but `latestRunDiff()` returns `null`, so changed-line counts are not a functioning row feature in this snapshot. [row], [indicators], [settings]
- **Actual card status:** Approval → Input → guest Request takes precedence in resolution, followed by runtime-derived Working/Waiting/Limited/Failed; otherwise Woke/Done/age. Working can be labeled **Goal**. Do not confuse this with the older generic status-pill helper, which also defines Plan Ready/Connecting/Completed. [logic], [row]
- **Subagents:** no separate sidebar rows or inline child-count field in the inspected row. An open child highlights its nearest non-subagent ancestor; pending child approval/input propagates into parent status. **Docs:** inspect children through Agents/conversation cards; agent-created children receive messages through the parent. [logic], [row], [docs]
- **Single menu:** new thread on branch; pin/unpin; settle/un-settle; snooze/wake; rename/regenerate title; mark unread; optional guest share; project filter; per-thread auto-settle setting; copy path/branch/ID; project settings; archive; delete. Double-click renames; Enter/Space activates. Capability and permission gates apply. [menu], [row]
- **Multi-select, current wiring:** Cmd/Ctrl-click toggles; Shift-click selects a visible-order range. Menu offers **Unpin** (pinned subset), **Settle**, **Snooze** (all eligible, including custom), **Regenerate titles** (eligible subset), **Mark unread**, **Delete**. No bulk pin/read/archive/un-settle/wake item here. **Trap:** `buildMultiSelectThreadContextMenuItems` in `Sidebar.logic.ts` still lists Archive, but the current `Sidebar.tsx` builds its own menu without it. Separate sweep gestures bulk settle/un-settle/wake within a section. [sidebar], [logic]
- **Navigation/recovery:** displayed-order jump/traversal; history back/forward; settle/snooze advances from the viewed row to another eligible thread. Opening a hidden thread through history/palette can widen project scope and reveal its row. **Docs:** desktop `mod+1…9` jumps, `mod+[` / `mod+]` history, and five-second grouped Undo for supported park/unpin/archive/draft-discard actions; terminal focus keeps native shortcuts. [sidebar], [keys], [docs]

## Transferable terminal design lessons (recommendations)

1. Model **open tab**, **selected row**, **execution state**, **attention/read state**, and **organization state** separately. “Close tab,” settle, archive and delete need distinct commands.
2. Start with a stable, keyboard-first pinned/active list plus optional shelves. Make Working folding explicit: it changes the ordering contract. Preserve manual order when switching modes; retain the current session in collapsed shelves.
3. Use scoped IDs (server/environment + session), never titles/branches as identity. Keep project scope orthogonal to grouping and search. On history navigation, reveal the destination rather than leaving an invisible active tab.
4. Spend terminal width on title + an unambiguous attention glyph/label; disclose branch, PR, model, environment and child details in a secondary line or inspector. Aggregate child attention into the parent and offer a child drill-down.
5. Define unread as a persisted watermark with explicit manual override behavior. Decide whether the plugin needs general unread messages or T3-style unseen completion; do not silently conflate them. Keep wake notifications distinct.
6. Give range selection and explicit bulk actions keyboard equivalents; show eligible counts and partial failures. Use reversible park/unpin actions with Undo. Prefer explicit state actions over requiring drag gestures.
7. Keep row updates local, shared clocks throttled, and expensive PR/git subscriptions limited to visible/current rows. Capability-gate integrations; a plugin cannot reproduce server-owned auto-settlement or reliable wake timers merely by hiding rows. [row], [logic], [visits], [docs]
